## 1. Today's Learning: Indexing & Performance

### What is an index?

An index helps MongoDB find documents faster.

Imagine a library with 10,000 books.

Without an index, you might need to check every book to find one.

With an index, you can quickly locate the book using its title or author.

MongoDB indexes work in a similar way.

### Without an index

MongoDB may perform a collection scan.

It checks many documents to find matching results.

### With an index

MongoDB can use an index to locate matching documents more efficiently.

## 2. Create Indexes in Mongoose

In our Learning Tracker API, we have a Project model.

We can create indexes for commonly searched fields.

Inside `models/Project.js`, add these indexes after your schema definition:

```js
projectSchema.index({ title: 1 });

projectSchema.index({ createdAt: -1 });

projectSchema.index({ author: 1 });

projectSchema.index({ author: 1, createdAt: -1 });
```

**Important:** Keep your existing text index from Day 166 and other schema indexes. Do not create a second text index on the same collection.

### Understanding the numbers

```js
projectSchema.index({ title: 1 });
```

- `1` means ascending order.
- `-1` means descending order.

Examples:

```js
projectSchema.index({ title: 1 });
projectSchema.index({ createdAt: -1 });
```

## 3. Understand Compound Indexes

A compound index uses multiple fields.

Example:

```js
projectSchema.index({
  author: 1,
  createdAt: -1
});
```

This can help queries that filter by author and sort by creation date.

The field order matters.

An index on `{ author: 1, createdAt: -1 }` is not automatically equivalent to an index on `{ createdAt: -1, author: 1 }`.

Do not create indexes for every field. Indexes use storage and can slow down database writes.

## 4. Check Indexes in MongoDB

Open MongoDB Atlas.

1. Open your database.
2. Select your database.
3. Open the `projects` collection.
4. Find the Indexes section.
5. Review the indexes created for your collection.

You can also use MongoDB Shell:

```js
db.projects.getIndexes()
```

## 5. Check Query Performance

MongoDB provides `explain()` to understand how a query runs.

Example:

```js
db.projects.find({
  title: "Learning Tracker"
}).explain("executionStats")
```

Important values:

- `COLLSCAN`: MongoDB scans the collection.
- `IXSCAN`: MongoDB uses an index.
- `totalDocsExamined`: Number of documents examined.
- `executionTimeMillis`: Execution time in milliseconds.

An index can improve query performance, but always measure actual queries instead of assuming every index helps.

## 6. Understand Deployment

Deployment means making our application available online.

Until now, our API has mainly run on our local computer.

After deployment:

- Other people can access the API.
- The backend runs on a hosting platform.
- MongoDB stores data in the cloud.
- The frontend can communicate with the deployed API.

Our deployment architecture:

```text
User
  |
  v
Frontend
  |
  v
Deployed Express API
  |
  v
Mongoose
  |
  v
MongoDB Atlas
```

## 7. Prepare MongoDB Atlas

We already use MongoDB Atlas for our database.

Before deployment:

1. Open MongoDB Atlas.
2. Select your project.
3. Open Database Access.
4. Check that your database user exists.
5. Open Network Access.
6. Configure network access for your hosting provider.
7. Copy your MongoDB connection string.

For production, prefer restricting network access to the addresses required by your hosting provider. Do not leave unrestricted database access enabled unnecessarily.

Your connection string should look similar to:

```text
mongodb+srv://USERNAME:PASSWORD@CLUSTER.mongodb.net/learning_tracker
```

Never put your real database password in GitHub.

## 8. Prepare the Express API

Make sure your `package.json` contains a start script.

Example:

```json
{
  "scripts": {
    "start": "node server.js",
    "dev": "nodemon server.js"
  }
}
```

Your server must listen on the port supplied by the hosting platform.

Example:

```js
const PORT = process.env.PORT || 5000;

app.listen(PORT, () => {
  console.log(`Server running on port ${PORT}`);
});
```

Connect to MongoDB before starting the server.

Example:

```js
require("dotenv").config();

const mongoose = require("mongoose");

const startServer = async () => {
  try {
    await mongoose.connect(process.env.MONGO_URI);

    console.log("MongoDB connected successfully");

    app.listen(process.env.PORT || 5000, () => {
      console.log("Server started successfully");
    });
  } catch (error) {
    console.error("Startup failed:", error.message);
    process.exit(1);
  }
};

startServer();
```

Adapt this to your existing `server.js`. Do not create a second Express app or database connection.

## 9. Deploy Using Render

For this learning task, we will use Render to host our Express API.

<text>Deployment platform: Render</text>

Website: https://render.com

### Steps

1. Create or sign in to your Render account.
2. Push your project to GitHub.
3. Open the Render dashboard.
4. Select **New**.
5. Select **Web Service**.
6. Connect your GitHub repository.
7. Select your Learning Tracker API repository.

Configure:

| Setting | Value |
|---|---|
| Name | learning-tracker-api |
| Runtime | Node |
| Build Command | `npm install` |
| Start Command | `npm start` |

If your API is inside a subdirectory, set the correct Root Directory.

## 10. Add Environment Variables

In your Render service settings, open Environment Variables.

Add:

| Key | Value |
|---|---|
| `MONGO_URI` | Your MongoDB Atlas connection string |
| `NODE_ENV` | `production` |

Render provides the `PORT` environment variable automatically.

Do not upload `.env` to GitHub.

Click **Deploy** and wait for the build and deployment to finish.

## 12. Common Deployment Problems

| Problem | Possible solution |
|---|---|
| Application failed to start | Check Render logs and start command |
| MongoDB connection failed | Check `MONGO_URI` |

| Network access denied | Review Atlas Network Access |
| Module not found | Check dependencies in `package.json` |
| API returns 404 | Check route paths |
| API works locally but not online | Check production environment variables |
