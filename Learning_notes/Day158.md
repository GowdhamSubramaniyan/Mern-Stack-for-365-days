## Part 1 — Creating documents

### What is a document?
- Database: stores related application data.
- Collection: holds related documents.
- Document: one individual record.

### Method 1: `Model.create()`
Creates and saves a document in one operation.

```js
const Item = require("../models/Item");

const newItem = await Item.create({
  name: "Laptop",
  price: 800,
  category: "Electronics",
});
```

Mongoose checks the schema, validates the data, saves it to MongoDB, and returns the created document.

### Method 2: `new Model()` and `.save()`
Creates a document first, then saves it separately.

```js
const item = new Item({
  name: "Keyboard",
  price: 50,
  category: "Electronics",
});

await item.save();
```

| Method | Meaning |
|---|---|
| `Item.create(data)` | Creates and saves in one operation |
| `new Item(data)` | Creates a Mongoose document in memory |
| `item.save()` | Saves that document to MongoDB |

Both `create()` and `save()` run Mongoose document validation.

## Part 2 — Schema validation

Validation checks whether data follows your schema rules before Mongoose saves it.

| Rule | Purpose |
|---|---|
| `required` | Makes a field mandatory |
| `trim` | Removes whitespace at the start and end of a string |
| `minlength` / `maxlength` | Sets minimum / maximum string length |
| `min` / `max` | Sets minimum / maximum number |
| `enum` | Allows only specified values |
| `default` | Supplies a value when one is not provided |

Example:

```js
price: {
  type: Number,
  required: true,
  min: 0,
  max: 10000,
}
```

This makes price mandatory and restricts it to the range 0–10,000.

## Part 3 — Add validation to your existing Item schema

Open your existing `models/Item.js`. Adapt this example to your project. **Do not remove fields your application already uses.**

```js
const mongoose = require("mongoose");

const itemSchema = new mongoose.Schema(
  {
    name: {
      type: String,
      required: [true, "Item name is required"],
      trim: true,
      minlength: [3, "Name must have at least 3 characters"],
      maxlength: [50, "Name cannot exceed 50 characters"],
    },
    price: {
      type: Number,
      required: [true, "Price is required"],
      min: [0, "Price cannot be negative"],
      max: [10000, "Price cannot exceed 10000"],
    },
    category: {
      type: String,
      enum: ["Electronics", "Clothing", "Food"],
      required: true,
    },
    inStock: {
      type: Boolean,
      default: true,
    },
  },
  { timestamps: true }
);

module.exports = mongoose.model("Item", itemSchema);
```

The category list is only an example. Change it to match the categories your application supports.

## Part 4 — Use validation when creating documents

Your existing POST controller should have logic similar to this:

```js
const createItem = async (req, res, next) => {
  try {
    const newItem = await Item.create(req.body);

    return res.status(201).json({
      success: true,
      data: newItem,
    });
  } catch (error) {
    next(error);
  }
};
```

`Item.create(req.body)` automatically runs schema validation before saving. You do not need to repeat every schema rule inside this controller.

### Handle validation errors

Make sure your Express error middleware handles Mongoose validation errors as `400 Bad Request`. For example, inside your existing error middleware:

```js
if (error.name === "ValidationError") {
  return res.status(400).json({
    success: false,
    message: error.message,
  });
}
```

Preserve your existing error-handling logic and place this before your general server-error response.

```js

  new: true,
  runValidators: true,
}
```
