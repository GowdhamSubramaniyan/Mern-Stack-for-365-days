## Part 1 — Learn: MongoDB update operators (30 minutes)

MongoDB update operators let you change particular fields without replacing the whole document.

Assume an item looks like this:

```js
{
  name: "Laptop",
  price: 800,
  category: "Electronics",
  tags: ["computer"]
}
```

### 1. `$set` — set or replace a field's value

```js
await Item.updateOne(
  { name: "Laptop" },
  { $set: { price: 900 } }
);
```

The laptop's price becomes `900`.

### 2. `$inc` — increase or decrease a number

```js
await Item.updateOne(
  { name: "Laptop" },
  { $inc: { price: 100 } }
);
```

The price increases by `100`. A negative number decreases it:

```js
{ $inc: { price: -50 } }
```

### 3. `$unset` — remove a field

```js
await Item.updateOne(
  { name: "Laptop" },
  { $unset: { category: "" } }
);
```

This removes the `category` field, not the whole document.

### 4. `$push` — add a value to an array

```js
await Item.updateOne(
  { name: "Laptop" },
  { $push: { tags: "electronics" } }
);
```

### 5. `$pull` — remove matching values from an array

```js
await Item.updateOne(
  { name: "Laptop" },
  { $pull: { tags: "computer" } }
);
```

| Operator | Purpose |
|---|---|
| `$set` | Set a field's value |
| `$inc` | Increase or decrease a number |
| `$unset` | Remove a field |
| `$push` | Add a value to an array |
| `$pull` | Remove matching values from an array |

**Remember:** `updateOne()` updates the first document matching its filter. Use a filter that identifies the intended document.

## Part 2 — Build: Reference between models (30 minutes)

### What is a reference?

Imagine a marketplace:

- One **Author** can create many **Items**.
- Each **Item** belongs to one **Author**.

Instead of copying the author's name and email into every item, store the author's MongoDB `_id` in the item. This is a one-to-many relationship.

### Step 1 — Check your Author model

If you created `Author.js` on Day 159, continue using it. A simple version is:

```js
const mongoose = require("mongoose");

const authorSchema = new mongoose.Schema(
  {
    name: {
      type: String,
      required: true,
      trim: true,
    },
    email: {
      type: String,
      required: true,
      unique: true,
      lowercase: true,
      trim: true,
    },
  },
  { timestamps: true }
);

module.exports = mongoose.model("Author", authorSchema);
```

`unique: true` creates a unique database index; it is not a normal Mongoose validator. Handle duplicate-key errors in your API.

### Step 2 — Add an author reference to your Item schema

Open your existing `models/Item.js`. Keep all existing fields and add this field inside the schema definition:

```js
author: {
  type: mongoose.Schema.Types.ObjectId,
  ref: "Author",
  required: true,
}
```

For example, your schema may look similar to this. Retain your own fields and options:

```js
const mongoose = require("mongoose");

const itemSchema = new mongoose.Schema(
  {
    name: {
      type: String,
      required: true,
      trim: true,
    },
    price: {
      type: Number,
      required: true,
      min: 0,
    },
    category: {
      type: String,
      required: true,
    },
    author: {
      type: mongoose.Schema.Types.ObjectId,
      ref: "Author",
      required: true,
    },
  },
  { timestamps: true }
);

module.exports = mongoose.model("Item", itemSchema);
```

- `ObjectId` stores the ID of another MongoDB document.
- `ref: "Author"` tells Mongoose which model that ID refers to.
- `required: true` means an item must have an author ID when it is validated.

### Step 3 — Create an author

You can use your existing author route, or temporarily run this in a test script:

```js
const Author = require("./models/Author");

const author = await Author.create({
  name: "Alex",
  email: "alex@example.com",
});

console.log(author._id);
```

Copy the generated `_id`. If you already have an author, use that author's existing ID.

### Step 4 — Create an item linked to that author

```js
const item = await Item.create({
  name: "Laptop",
  price: 800,
  category: "Electronics",
  author: author._id,
});
```

In a real API, the author ID should normally come from an existing author selected by the application. Do not create a new author every time an item is created.

Example JSON request body:

```json
{
  "name": "Laptop",
  "price": 800,
  "category": "Electronics",
  "author": "YOUR_AUTHOR_OBJECT_ID"
}
```

Replace `YOUR_AUTHOR_OBJECT_ID` with a real author `_id`.

### Step 5 — Retrieve author details with `populate()`

Without `populate()`, the query returns the author ID:

```js
const item = await Item.findById(itemId);
```

With `populate()`, Mongoose retrieves the referenced author document:

```js
const item = await Item.findById(itemId).populate("author");
```

You can select only the fields you need:

```js
const item = await Item.findById(itemId)
  .populate("author", "name email");
```

The result contains an `author` object with those details instead of only the ID.

### Step 6 — Add `populate()` to your existing GET-by-ID controller

Update the query line in your existing controller:

```js
const item = await Item.findById(id).populate("author", "name email");
```

Keep your existing ID validation, 404 response, response format, `try/catch`, and error handling. You only need to change the query.

### Important validation note

A `ref` does **not** guarantee that the author document exists. Before creating an item, check the supplied author ID:

```js
const author = await Author.findById(req.body.author);

if (!author) {
  return res.status(404).json({
    success: false,
    message: "Author not found",
  });
}
```

Then use the verified author's `_id` when creating the item.

If you add `required: true` to a schema that already has old items without an author, those old documents may fail validation during later updates that run validators. You can migrate old documents or make the reference optional temporarily while transitioning.
