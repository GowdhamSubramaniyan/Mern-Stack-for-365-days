## Part 1 — Querying MongoDB with Mongoose

A query asks MongoDB to find documents that match a condition.

### 1. `find()` — retrieve multiple documents

```js
// Find every item
const items = await Item.find();

// Find only Electronics items
const electronics = await Item.find({
  category: "Electronics",
});
```

`find()` returns an array. If no documents match, it returns an empty array.

### 2. `findById()` — retrieve one document by its ID

```js
const item = await Item.findById(itemId);
```

It returns the matching document, or `null` if no document exists.

### 3. `findOne()` — retrieve the first matching document

```js
const item = await Item.findOne({
  name: "Laptop",
});
```

It returns one matching document, or `null`.

### 4. Useful query operators

```js
// Price greater than 100
const expensiveItems = await Item.find({
  price: { $gt: 100 },
});

// Price less than 500
const affordableItems = await Item.find({
  price: { $lt: 500 },
});

// Price greater than or equal to 100
const itemsFrom100 = await Item.find({
  price: { $gte: 100 },
});
```

| Operator | Meaning |
|---|---|
| `$gt` | Greater than |
| `$lt` | Less than |
| `$gte` | Greater than or equal to |
| `$lte` | Less than or equal to |
| `$ne` | Not equal to |

**Remember:**

- `find()` — multiple documents (array).
- `findById()` — one document by `_id`.
- `findOne()` — one document matching a filter.

## Part 2 — Create a second model: Author

Imagine a marketplace. Each item is listed by an author.

Instead of copying the author's name and email into every item, we can store author information in a separate collection. The Item document stores a reference to the Author document.

### 5. Create `models/Author.js`

Add a new file alongside your existing `Item.js` model:

```js
const mongoose = require("mongoose");

const authorSchema = new mongoose.Schema(
  {
    name: {
      type: String,
      required: true,
      trim: true,
    },

    email: {
      type: String,
      required: true,
      unique: true,
      lowercase: true,
      trim: true,
    },
  },
  {
    timestamps: true,
  }
);

module.exports = mongoose.model("Author", authorSchema);
```

What the fields mean:

- `name`: author's name.
- `email`: author's email address.
- `timestamps`: Mongoose automatically adds `createdAt` and `updatedAt`.
- `unique: true`: creates a unique index so duplicate email values are rejected by MongoDB. It is not a normal Mongoose validator, so handle duplicate-key errors in your API.

Mongoose will use the `authors` collection by default.

### 6. Add an Author reference to `Item.js`

Inside your existing Item schema, add this field:

```js
author: {
  type: mongoose.Schema.Types.ObjectId,
  ref: "Author",
  required: true,
},
```

Example of how the field fits inside a schema:

```js
const itemSchema = new mongoose.Schema({
  name: {
    type: String,
    required: true,
  },

  price: {
    type: Number,
    required: true,
    min: 0,
  },

  author: {
    type: mongoose.Schema.Types.ObjectId,
    ref: "Author",
    required: true,
  },
});
```

Keep your existing fields and options; add the `author` field rather than replacing your entire schema.

**What does this reference mean?**

- `ObjectId` stores the ID of another MongoDB document.
- `ref: "Author"` tells Mongoose that the ID refers to the Author model.
- `required: true` means new Item documents must include an author.

**Important for an existing project:** If you already have Item documents without an author, making this field required can cause validation failures when updating those documents. You may need to assign authors to existing items, or make the field optional while migrating your data.

## Part 3 — Create and connect documents

### 7. Create an Author document

You can do this in a temporary test script or in an Author controller:

```js
const Author = require("../models/Author");

const author = await Author.create({
  name: "Gowdham",
  email: "gowdham@example.com",
});

console.log(author);
```

`Author.create()` validates the data and saves the new document to MongoDB.

Use an email address that has not already been used in your database.

### 8. Create an Item linked to that Author

After creating the author, use its `_id` when creating an item:

```js
const Item = require("../models/Item");

const item = await Item.create({
  name: "Laptop",
  price: 800,
  category: "Electronics",
  author: author._id,
});
```

The Item document stores the author's ID in its `author` field.

If your existing Item schema has other required fields, include those too.

### 9. Use `populate()` to retrieve Author details

Without `populate()`, a query returns the author's ObjectId:

```js
const item = await Item.findById(itemId);
```

To retrieve the referenced author's details as well:

```js
const item = await Item.findById(itemId)
  .populate("author");
```

You can select only certain author fields:

```js
const item = await Item.findById(itemId)
  .populate("author", "name email");
```

`populate()` does not merge the two collections permanently. It retrieves the referenced document when you run the query.

## Part 4 — Practical testing

Complete these steps in your existing project:

1. Run your Express application and confirm the MongoDB connection works.
2. Create an Author document with a new email address.
3. Copy or capture the returned author `_id`.
4. Create an Item using that ID in its `author` field.
5. Query the item with `Item.findById(itemId)`.
6. Query it again with `.populate("author")`.
7. Check the `authors` and `items` collections in MongoDB Atlas or Compass.

### Expected relationship

The Item document stores a reference similar to:

```json
{
  "name": "Laptop",
  "price": 800,
  "author": "THE_AUTHOR_OBJECT_ID"
}
```

After using `populate("author")`, the query result includes the author's selected details.

### Common problems

- **`author` is null:** Check that the Item's `author` field contains the correct Author `_id`.
- **Populate does not work:** Check that the reference says `ref: "Author"` and that the model is registered as `mongoose.model("Author", authorSchema)`.
- **Duplicate email error:** Use a different email address; the unique index prevents duplicates.
- **Validation error on old items:** Existing documents may not have an author. Assign one or plan a migration before making the field required.
- **Invalid ObjectId:** Make sure the ID is copied correctly from MongoDB.

## Key takeaways

1. `find()` returns an array of matching documents.
2. `findById()` finds one document using its `_id`.
3. `findOne()` finds the first document matching a filter.
4. A second model gives related data its own collection.
5. `ObjectId` and `ref` define a reference between models.
6. `populate()` retrieves the referenced document's details.
