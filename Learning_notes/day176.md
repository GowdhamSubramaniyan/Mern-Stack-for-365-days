## 1. Today's Learning: Environment Safety & Secrets

When building an application, we often need private information such as:

- MongoDB connection strings
- Database usernames and passwords
- API keys
- JWT secret keys
- Email service credentials

These are called **secrets**.

We should never publish these secrets on GitHub.

### What is an environment variable?

An environment variable stores configuration outside our application source code.

For example, instead of writing our MongoDB connection string directly inside `server.js`, we store it in a `.env` file.

**Bad practice:**

```js
mongoose.connect("mongodb+srv://username:password@cluster.mongodb.net/myDatabase");
```

Anyone who can access this source code could see the credentials.

**Better practice:**

```js
mongoose.connect(process.env.MONGO_URI);
```

The actual connection string stays inside `.env`.

## 2. Install dotenv

The `dotenv` package loads environment variables from a `.env` file into `process.env`.

Install it:

```bash
npm install dotenv
```

## 3. Create a .env File

Create a `.env` file in the root of your project.

```env
PORT=5000

MONGO_URI=mongodb+srv://YOUR_USERNAME:YOUR_PASSWORD@YOUR_CLUSTER.mongodb.net/learning_tracker

NODE_ENV=development
```

Replace the example connection string with your own MongoDB Atlas connection string.

**Important:**
- Never share your real MongoDB password.
- Never commit `.env` to GitHub.
- Do not put secrets inside frontend JavaScript.
- Do not upload screenshots showing your credentials.

## 4. Protect Secrets with .gitignore

Create or update `.gitignore` in your project root.

```gitignore
# Environment variables
.env
.env.*
!.env.example

# Dependencies
node_modules/

# Logs
*.log
npm-debug.log*

# Operating system files
.DS_Store
Thumbs.db

# Coverage reports
coverage/
```

This prevents Git from tracking your real environment files and other unnecessary files.

**Important:** If `.env` was already committed to Git, adding it to `.gitignore` does not remove it from Git history. You must remove it from tracking and rotate any exposed credentials.

If it was committed previously, run:

```bash
git rm --cached .env
git add .gitignore
git commit -m "Remove environment file from tracking"
```

Then change any credentials that were exposed.

## 5. Create a Safe .env.example File

Other developers need to know which environment variables are required.

Create `.env.example`.

```env
PORT=5000
MONGO_URI=your_mongodb_connection_string
NODE_ENV=development
```

This file contains placeholders, not real credentials.

It is safe to commit this example file to GitHub.

## 6. Load Environment Variables in server.js

At the beginning of your server entry point, load dotenv before accessing environment variables.

```js
require("dotenv").config();

const mongoose = require("mongoose");

const PORT = process.env.PORT || 5000;
const MONGO_URI = process.env.MONGO_URI;
const NODE_ENV = process.env.NODE_ENV || "development";

if (!MONGO_URI) {
  console.error("MONGO_URI is missing from environment variables");
  process.exit(1);
}

const connectDB = async () => {
  try {
    await mongoose.connect(MONGO_URI);
    console.log("MongoDB connected successfully");
  } catch (error) {
    console.error("MongoDB connection failed:", error.message);
    process.exit(1);
  }
};
```

Call `connectDB()` before starting your Express server.

If you already have a working database connection, update your existing code rather than creating a second connection.

## 7. Add Basic Express Security

Install these packages:

```bash
npm install helmet express-rate-limit
```

### A. Helmet

Helmet adds security-related HTTP headers.

In your Express application:

```js
const helmet = require("helmet");

app.use(helmet());
```

### B. Rate Limiting

Rate limiting helps prevent users from sending too many requests in a short period.

```js
const rateLimit = require("express-rate-limit");

const apiLimiter = rateLimit({
  windowMs: 15 * 60 * 1000,
  limit: 100,
  standardHeaders: "draft-8",
  legacyHeaders: false,
  message: {
    message: "Too many requests. Please try again later."
  }
});

app.use("/api", apiLimiter);
```

This example allows up to 100 requests per 15-minute window per client IP.

For a real application, configure the limiter according to your traffic and infrastructure.

## 8. Protect Your MongoDB Database

MongoDB Atlas provides security controls.

Review these settings in your Atlas dashboard:

1. Open your MongoDB Atlas project.
2. Go to Database Access.
3. Check your database users.
4. Remove users you no longer need.
5. Use strong, unique passwords.
6. Give each database user only the permissions they require.
7. Open Network Access.
8. Review which IP addresses are allowed to connect.

Avoid allowing access from every IP address (`0.0.0.0/0`) unless you have a specific, justified reason and appropriate additional security controls.

## 9. Validate Environment Variables

Applications should fail early when required configuration is missing.

Create `config/env.js`:

```js
require("dotenv").config();

const requiredVariables = ["MONGO_URI"];

for (const variable of requiredVariables) {
  if (!process.env[variable]) {
    throw new Error(
      `Missing required environment variable: ${variable}`
    );
  }
}

module.exports = {
  PORT: process.env.PORT || 5000,
  MONGO_URI: process.env.MONGO_URI,
  NODE_ENV: process.env.NODE_ENV || "development"
};
```

Now import the configuration in your server:

```js
const config = require("./config/env");

console.log(`Starting application in ${config.NODE_ENV} mode`);
```

Use `config.MONGO_URI` when connecting to MongoDB.

Do not log the actual connection string.

## 10. Security Checklist for Our API

| Security check | Why it matters |
|---|---|
| `.env` in `.gitignore` | Prevents accidental secret uploads |
| `.env.example` | Shows required configuration safely |
| Strong database password | Protects database access |
| Restricted Atlas IP access | Limits network access |
| Helmet | Adds HTTP security headers |
| Rate limiting | Helps reduce excessive requests |
| Input validation | Rejects invalid user input |
| Error middleware | Avoids exposing internal errors |
| No secrets in frontend | Keeps private credentials on the server |
| Least-privilege database user | Limits damage if credentials leak |

### Test 3: Check Git tracking

Run:

```bash
git status
```

Your `.env` file should not appear as a file ready to be committed.

You can also check:

```bash
git check-ignore -v .env
```

Git should show the `.gitignore` rule that ignores it.

### Test 4: Check security middleware

Start the server and send a request to:

```text
GET http://localhost:5000/api/projects
```

Check that the API still works and that security headers are present in the response.
