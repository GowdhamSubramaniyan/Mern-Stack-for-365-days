## Part 1 — Schema types

### 1. What is a schema?
A Mongoose schema is a blueprint defining a document's fields, data types, and rules.

```js
const mongoose = require("mongoose");

const itemSchema = new mongoose.Schema({
  name: String,
  price: Number,
  category: String,
  inStock: Boolean,
});
```

### 2. Common schema types

| Type | Stores | Example |
|---|---|---|
| `String` | Text | `"Laptop"` |
| `Number` | Numeric values | `800` |
| `Boolean` | True or false | `true` |
| `Date` | Date and time | `new Date()` |
| `Array` | A list of values | `["red", "blue"]` |
| `ObjectId` | MongoDB document IDs/references | `mongoose.Schema.Types.ObjectId` |
| `Mixed` | Flexible values | Different structures |

Examples:

```js
tags: [String],

createdAt: {
  type: Date,
  default: Date.now,
},

owner: {
  type: mongoose.Schema.Types.ObjectId,
  ref: "User",
},
```

## Part 2 — Schema validation

### 3. What is validation?
Validation checks whether data follows your schema rules before Mongoose saves or updates it. For example, you can prevent an empty name or negative price.

| Option | Purpose |
|---|---|
| `required: true` | Field must be provided |
| `trim: true` | Removes whitespace at the start and end |
| `minlength` / `maxlength` | Minimum / maximum string length |
| `min` / `max` | Minimum / maximum number |
| `enum` | Restricts values to a predefined list |
| `default` | Supplies a value when none is provided |

### 4. Example Item schema

Adapt this to your existing `models/Item.js`. **Do not remove fields your project already needs.**

```js
const mongoose = require("mongoose");

const itemSchema = new mongoose.Schema(
  {
    name: {
      type: String,
      required: [true, "Item name is required"],
      trim: true,
      minlength: [3, "Name must contain at least 3 characters"],
      maxlength: [50, "Name cannot exceed 50 characters"],
    },
    price: {
      type: Number,
      required: [true, "Price is required"],
      min: [0, "Price cannot be negative"],
    },
    category: {
      type: String,
      enum: ["Electronics", "Clothing", "Food"],
    },
    inStock: {
      type: Boolean,
      default: true,
    },
  },
  { timestamps: true }
);

module.exports = mongoose.model("Item", itemSchema);
```

The category list is only an example. Change it to match your application.

**Validation on updates:** Your Day 156 `findByIdAndUpdate()` controller should retain `runValidators: true`, because update validators are not enabled by default.

```js
{
  new: true,
  runValidators: true,
}
```

## Part 3 — Build the DELETE endpoint

### 5. What does DELETE do?
Your API supports these CRUD operations:

| Operation | HTTP method | Purpose |
|---|---|---|
| Create | `POST` | Add an item |
| Read | `GET` | Retrieve items |
| Update | `PUT` | Update an item |
| Delete | `DELETE` | Remove an item |

A DELETE request identifies an item by its MongoDB `_id`, then asks Mongoose to delete it.

### 6. Add the delete controller

Open your existing `controllers/itemController.js`. Ensure these imports exist:

```js
const mongoose = require("mongoose");
const Item = require("../models/Item");
```

Add this function. Do not remove your existing controller functions.

```js
const deleteItem = async (req, res, next) => {
  try {
    const { id } = req.params;

    if (!mongoose.isValidObjectId(id)) {
      return res.status(400).json({
        success: false,
        message: "Invalid item ID",
      });
    }

    const deletedItem = await Item.findByIdAndDelete(id);

    if (!deletedItem) {
      return res.status(404).json({
        success: false,
        message: "Item not found",
      });
    }

    return res.status(200).json({
      success: true,
      message: "Item deleted successfully",
      data: deletedItem,
    });
  } catch (error) {
    next(error);
  }
};
```

**Understand the key method:**

```js
const deletedItem = await Item.findByIdAndDelete(id);
```

- `Item` is your Mongoose model.
- `findByIdAndDelete()` finds a document by `_id` and deletes it.
- `id` comes from the request URL.
- `await` waits for MongoDB to finish.
- `deletedItem` contains the deleted document, or `null` if none matched.

### 7. Export the controller

Add `deleteItem` to your existing exports. For example:

```js
module.exports = {
  createItem,
  getAllItems,
  getItemById,
  updateItem,
  deleteItem,
};
```

Keep any other exports your project already uses.

### 8. Add the DELETE route

In your existing `routes/itemRoutes.js`, import `deleteItem` from the controller and add:

```js
router.delete("/:id", deleteItem);
```

If your router is mounted at `/api/items`, the endpoint is:

```text
DELETE /api/items/:id
```

Use the actual base path and port configured in your project. Do not create a second router or a second `app.listen()` for this feature.

## Part 4 — Test the endpoint

### 9. Test using Postman

Start your existing Express server and send a DELETE request:

```text
DELETE http://localhost:5000/api/items/YOUR_ITEM_ID
```

Replace `YOUR_ITEM_ID` with the `_id` of an item that exists. Adjust the port or base path if necessary.

Expected successful response — **200 OK**:

```json
{
  "success": true,
  "message": "Item deleted successfully",
  "data": {
    "_id": "671abc123456789012345678",
    "name": "Laptop",
    "price": 800
  }
}
```

The `data` object is an example; your actual document fields may differ.

### Test these cases

| Test | Expected status | Meaning |
|---|---:|---|
| Valid ID of an existing item | `200` | Item deleted |
| Valid-format ID with no matching item | `404` | Item not found |
| Invalid ID format | `400` | Invalid request parameter |

### 10. Verify in MongoDB
1. Open MongoDB Atlas or MongoDB Compass.
2. Open your database and the `items` collection.
3. Find the document you deleted.
4. Confirm it is no longer in the collection.
