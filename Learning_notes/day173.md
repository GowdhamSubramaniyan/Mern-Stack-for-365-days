## 1. What is Database Seeding?

Database seeding means automatically inserting sample data into a database.

For example, when we create a new application, our MongoDB database might be empty.

Instead of manually adding projects using Postman, we can create a seed script that inserts sample authors and projects automatically.

### Benefits of Seeding

- Quickly creates sample data.
- Makes testing easier.
- Saves development time.
- Helps developers work with a populated database.

## 2. Important Seeding Methods

### insertMany()

Inserts multiple documents into a collection.

```js
await Project.insertMany([
  {
    title: "Portfolio Website",
    description: "A personal portfolio website",
    author: author._id
  },
  {
    title: "Learning Tracker",
    description: "An application to track learning progress",
    author: author._id
  }
]);
```

### create()

Creates and saves a single document.

```js
const author = await Author.create({
  name: "John Smith",
  email: "john@example.com"
});
```

### findOneAndUpdate()

Can find an existing document and update it, or create it if it doesn't exist using `upsert`.

```js
await Author.findOneAndUpdate(
  { email: "john@example.com" },
  {
    $set: { name: "John Smith" }
  },
  {
    upsert: true,
    new: true,
    runValidators: true
  }
);
```

This helps prevent creating duplicate seed records when the script is run repeatedly.

## 3. What is Soft Delete?

Normally, when we delete a document using:

```js
await Project.findByIdAndDelete(id);
```

The document is permanently removed from MongoDB.

But sometimes we don't want to permanently delete data.

Instead, we want to hide it while keeping it in the database.

This is called **Soft Delete**.

### Simple Example

Imagine a user deletes a project.

Instead of removing the project, we update its `deletedAt` field.

Before deletion:

```json
{
  "title": "Portfolio Website",
  "deletedAt": null
}
```

After deletion:

```json
{
  "title": "Portfolio Website",
  "deletedAt": "2026-11-20T12:00:00.000Z"
}
```

The project still exists in MongoDB, but it is marked as deleted.

## 4. Why Use Soft Delete?

- Recover accidentally deleted records.
- Preserve historical information.
- Maintain data for auditing.
- Avoid permanent data loss.
- Allow administrators to restore records.

## 5. Build: Add Soft Delete to Project Schema

Open your existing `models/Project.js`.

Add this field inside your existing schema:

```js
deletedAt: {
  type: Date,
  default: null
}
```

Example:

```js
const projectSchema = new mongoose.Schema({
  title: {
    type: String,
    required: true
  },

  description: {
    type: String
  },

  author: {
    type: mongoose.Schema.Types.ObjectId,
    ref: "Author",
    required: true
  },

  deletedAt: {
    type: Date,
    default: null
  }

}, { timestamps: true });
```

**Important:** Keep all your existing fields, indexes, virtuals and middleware. Only add the `deletedAt` field.

## 6. Implement Soft Delete Controller

Instead of permanently deleting the project, update its `deletedAt` field.

Add this function to your existing `projectController.js`:

```js
const softDeleteProject = async (req, res, next) => {
  try {
    const { id } = req.params;

    if (!mongoose.isValidObjectId(id)) {
      return res.status(400).json({
        message: "Invalid project ID"
      });
    }

    const project = await Project.findOneAndUpdate(
      {
        _id: id,
        deletedAt: null
      },
      {
        $set: {
          deletedAt: new Date()
        }
      },
      {
        new: true
      }
    );

    if (!project) {
      return res.status(404).json({
        message: "Project not found or already deleted"
      });
    }

    res.status(200).json({
      message: "Project moved to deleted items",
      project
    });

  } catch (error) {
    next(error);
  }
};
```

Make sure `mongoose` is imported:

```js
const mongoose = require("mongoose");
```

Add `softDeleteProject` to your existing controller exports. Do not remove your other functions.

## 7. Hide Deleted Projects

When fetching projects, we should only return documents that have not been deleted.

Update the query in your existing get-projects controller:

```js
const projects = await Project.find({
  deletedAt: null
})
.populate("author", "name email")
.sort({ createdAt: -1 });
```

This ensures soft-deleted projects are not shown in the normal project list.

Remember to apply the same filter to other normal queries, such as getting one project by ID and searching projects.

For example:

```js
const project = await Project.findOne({
  _id: req.params.id,
  deletedAt: null
});
```

For text search:

```js
const projects = await Project.find({
  deletedAt: null,
  $text: {
    $search: q
  }
});
```

## 8. Add Restore Functionality

One advantage of soft delete is that we can restore deleted projects.

Add this controller:

```js
const restoreProject = async (req, res, next) => {
  try {
    const { id } = req.params;

    if (!mongoose.isValidObjectId(id)) {
      return res.status(400).json({
        message: "Invalid project ID"
      });
    }

    const project = await Project.findOneAndUpdate(
      {
        _id: id,
        deletedAt: { $ne: null }
      },
      {
        $set: {
          deletedAt: null
        }
      },
      {
        new: true
      }
    );

    if (!project) {
      return res.status(404).json({
        message: "Deleted project not found"
      });
    }

    res.status(200).json({
      message: "Project restored successfully",
      project
    });

  } catch (error) {
    next(error);
  }
};
```

Add `restoreProject` to your existing controller exports.

## 9. Add Routes

Inside your existing `projectRoutes.js`, add:

```js
router.delete("/:id/soft-delete", softDeleteProject);

router.patch("/:id/restore", restoreProject);
```

Import both controller functions.

Place these routes before any conflicting dynamic routes if necessary.
