## 1. Today's Learning: Connecting Your API to the Database

An API needs a database to store and retrieve information.

In our project, we use:

- **Express.js** – handles API requests.
- **Mongoose** – connects Node.js to MongoDB.
- **MongoDB** – stores our project data.
- **Controllers** – handle requests and responses.
- **Services** – contain the database operations and business logic.

### How does the API connect to MongoDB?

The flow looks like this:

Client → Route → Controller → Service → Model → MongoDB

Example:

1. A user sends a request to `/api/projects`.
2. The route sends the request to the controller.
3. The controller calls the service.
4. The service uses the Mongoose model.
5. MongoDB returns the data.
6. The controller sends the response to the user.

## 2. What Is Controller Refactoring?

Refactoring means improving existing code without changing what the application does.

Previously, our controller handled everything:

- Reading request data.
- Validating input.
- Communicating with MongoDB.
- Handling errors.
- Sending responses.

This can make controllers difficult to maintain.

We can separate database operations into service files.

### Before Refactoring

```js
const getProjects = async (req, res, next) => {
  try {
    const projects = await Project.find({
      deletedAt: null
    }).populate("author", "name email");

    res.status(200).json(projects);
  } catch (error) {
    next(error);
  }
};
```

The controller directly communicates with MongoDB.

### After Refactoring

The controller calls a service, and the service communicates with MongoDB.

This keeps our code organised.

## 4. Build the Project Service

Create `services/projectService.js`.

The service contains the database operations.

```js
const Project = require("../models/Project");

// Get all active projects
const getAllProjects = async (filter = {}, options = {}) => {
  const {
    sort = { createdAt: -1 },
    skip = 0,
    limit = 10
  } = options;

  const projects = await Project.find({
    ...filter,
    deletedAt: null
  })
    .populate("author", "name email")
    .sort(sort)
    .skip(skip)
    .limit(limit);

  return projects;
};

// Get one active project
const getProjectById = async (id) => {
  return await Project.findOne({
    _id: id,
    deletedAt: null
  }).populate("author", "name email");
};

// Create a project
const createProject = async (projectData) => {
  return await Project.create(projectData);
};

// Update a project
const updateProject = async (id, updateData) => {
  return await Project.findOneAndUpdate(
    {
      _id: id,
      deletedAt: null
    },
    updateData,
    {
      new: true,
      runValidators: true
    }
  ).populate("author", "name email");
};

// Delete a project permanently
const deleteProject = async (id) => {
  return await Project.findOneAndDelete({
    _id: id,
    deletedAt: null
  });
};

// Count active projects
const countProjects = async (filter = {}) => {
  return await Project.countDocuments({
    ...filter,
    deletedAt: null
  });
};

module.exports = {
  getAllProjects,
  getProjectById,
  createProject,
  updateProject,
  deleteProject,
  countProjects
};
```

**Important:** This service uses your existing `Project` model and assumes it has a `deletedAt` field. It keeps the author population and pagination features from previous tasks.

## 5. Refactor the Project Controller

Open `controllers/projectController.js`.

Import the service:

```js
const mongoose = require("mongoose");

const projectService = require("../services/projectService");
```

Add or update your controller functions:

```js
// GET all projects
const getProjects = async (req, res, next) => {
  try {
    const {
      page = 1,
      limit = 10,
      sort = "newest",
      author,
      title
    } = req.query;

    const currentPage = Math.max(1, Number(page) || 1);
    const perPage = Math.min(100, Math.max(1, Number(limit) || 10));

    const filter = {};

    if (author) {
      if (!mongoose.isValidObjectId(author)) {
        return res.status(400).json({
          message: "Invalid author ID"
        });
      }

      filter.author = author;
    }

    if (title) {
      filter.title = {
        $regex: title,
        $options: "i"
      };
    }

    let sortOption = { createdAt: -1 };

    if (sort === "oldest") {
      sortOption = { createdAt: 1 };
    } else if (sort === "title_asc") {
      sortOption = { title: 1 };
    } else if (sort === "title_desc") {
      sortOption = { title: -1 };
    }

    const skip = (currentPage - 1) * perPage;

    const projects = await projectService.getAllProjects(
      filter,
      {
        sort: sortOption,
        skip,
        limit: perPage
      }
    );

    const totalProjects = await projectService.countProjects(filter);

    res.status(200).json({
      page: currentPage,
      limit: perPage,
      totalProjects,
      totalPages: Math.ceil(totalProjects / perPage),
      projects
    });
  } catch (error) {
    next(error);
  }
};

// GET one project
const getProjectById = async (req, res, next) => {
  try {
    const { id } = req.params;

    if (!mongoose.isValidObjectId(id)) {
      return res.status(400).json({
        message: "Invalid project ID"
      });
    }

    const project = await projectService.getProjectById(id);

    if (!project) {
      return res.status(404).json({
        message: "Project not found"
      });
    }

    res.status(200).json(project);
  } catch (error) {
    next(error);
  }
};

// CREATE project
const createProject = async (req, res, next) => {
  try {
    const project = await projectService.createProject(req.body);

    res.status(201).json({
      message: "Project created successfully",
      project
    });
  } catch (error) {
    next(error);
  }
};

// UPDATE project
const updateProject = async (req, res, next) => {
  try {
    const { id } = req.params;

    if (!mongoose.isValidObjectId(id)) {
      return res.status(400).json({
        message: "Invalid project ID"
      });
    }

    const project = await projectService.updateProject(id, req.body);

    if (!project) {
      return res.status(404).json({
        message: "Project not found"
      });
    }

    res.status(200).json({
      message: "Project updated successfully",
      project
    });
  } catch (error) {
    next(error);
  }
};

// DELETE project permanently
const deleteProject = async (req, res, next) => {
  try {
    const { id } = req.params;

    if (!mongoose.isValidObjectId(id)) {
      return res.status(400).json({
        message: "Invalid project ID"
      });
    }

    const project = await projectService.deleteProject(id);

    if (!project) {
      return res.status(404).json({
        message: "Project not found"
      });
    }

    res.status(200).json({
      message: "Project deleted successfully"
    });
  } catch (error) {
    next(error);
  }
};

module.exports = {
  getProjects,
  getProjectById,
  createProject,
  updateProject,
  deleteProject
};
```

**Important:** If your existing controller also exports search, statistics, soft-delete, restore, or review functions, keep those exports. Do not remove them. Refactor them separately when needed.

## 6. Understand the Difference

| Controller | Service |
|---|---|
| Handles HTTP requests | Handles database operations |
| Reads `req.params` and `req.body` | Receives normal JavaScript values |
| Sends responses with `res.json()` | Returns data |
| Chooses HTTP status codes | Uses Mongoose models |
| Passes errors to middleware | Throws database errors |

Example:

```js
// Controller
const project = await projectService.getProjectById(id);

// Service
return await Project.findById(id);
```

The controller does not need to know how the database query works.

## 7. Connect the API to MongoDB

In `server.js`, make sure MongoDB connects before the server starts listening.

```js
const mongoose = require("mongoose");
require("dotenv").config();

const app = require("./app");

const PORT = process.env.PORT || 5000;

const startServer = async () => {
  try {
    await mongoose.connect(process.env.MONGO_URI);

    console.log("MongoDB connected successfully");

    app.listen(PORT, () => {
      console.log(`Server running on port ${PORT}`);
    });
  } catch (error) {
    console.error("Database connection failed:", error.message);
    process.exit(1);
  }
};

startServer();
```

If your application currently defines Express inside `server.js`, keep that setup and apply the same connection logic there. Do not import `./app` unless you actually have an `app.js` file exporting your Express application.

Your `.env` file should contain:

```env
MONGO_URI=your_mongodb_connection_string
PORT=5000
```

Never upload your real `.env` file or database password to GitHub.

## 9. Why Is This Refactoring Useful?

Imagine our application grows from 5 API endpoints to 50.

If all database operations are inside controllers, the code becomes difficult to maintain.

By separating controllers and services:

- Controllers become smaller.
- Database logic stays organised.
- Code becomes easier to test.
- Services can be reused.
- Debugging becomes easier.
- Future changes become simpler.

This is an important step towards building professional backend applications.
