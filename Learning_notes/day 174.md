## 1. What are Schema Design Patterns?

Schema design means deciding how to organise and store data in MongoDB.

A good schema makes an application easier to maintain, faster to query, and easier to scale.

There are two common ways to store related data:

1. Embedding
2. Referencing

## 2. Embedding Pattern

Embedding means storing related data inside the same document.

Example:

```js
const projectSchema = new mongoose.Schema({
  title: {
    type: String,
    required: true
  },

  description: String,

  reviews: [
    {
      comment: String,
      rating: Number
    }
  ]
});
```

Here, reviews are stored inside the project document.

### When should we use embedding?

- When related data is small.
- When data is usually accessed together.
- When related data belongs to one parent document.

Example: Project reviews, addresses, and settings.

## 3. Referencing Pattern

Referencing means storing the ObjectId of another document instead of copying all its information.

Example:

```js
const projectSchema = new mongoose.Schema({
  title: String,

  author: {
    type: mongoose.Schema.Types.ObjectId,
    ref: "Author"
  }
});
```

The project stores the author's ID.

We can retrieve the author's information using `populate()`.

```js
const projects = await Project.find()
  .populate("author", "name email");
```

### When should we use referencing?

- When related data is shared by many documents.
- When related data changes independently.
- When related data is large.
- When we need to manage related records separately.

## 4. Embedding vs Referencing

| Embedding | Referencing |
|---|---|
| Stores data inside a document | Stores another document's ObjectId |
| Easy to retrieve together | Uses populate() to retrieve related data |
| Good for small related data | Good for shared related data |
| Can increase document size | Keeps documents separate |

In my Projects API:

- Reviews can be embedded inside a project.
- Authors are referenced using ObjectId.

# Part 2 – Build Sorting and Filters

## 5. What is Sorting?

Sorting means arranging database records in a particular order.

For example, we might want to display:

- Newest projects first.
- Oldest projects first.
- Projects in alphabetical order.

Mongoose provides the `sort()` method.

### Ascending Order

```js
const projects = await Project.find()
  .sort({ title: 1 });
```

`1` means ascending order.

### Descending Order

```js
const projects = await Project.find()
  .sort({ createdAt: -1 });
```

`-1` means descending order.

## 6. What are Filters?

Filters allow users to retrieve only documents that match specific conditions.

For example:

- Find projects by author.
- Find projects by title.
- Find projects created after a particular date.

Example:

```js
const projects = await Project.find({
  title: "Learning Tracker"
});
```

This returns projects matching the title.

### Filter by Author

```js
const projects = await Project.find({
  author: authorId
});
```

### Filter by Date

```js
const projects = await Project.find({
  createdAt: {
    $gte: new Date("2026-01-01")
  }
});
```

`$gte` means greater than or equal to.

## 7. Implement Sorting and Filters in Projects API

Update your existing `getProjects` controller.

This example supports:

- Sorting.
- Filtering by author.
- Searching by title.
- Pagination.
- Excluding soft-deleted projects.

```js
const getProjects = async (req, res, next) => {
  try {
    const {
      page = 1,
      limit = 10,
      sort = "newest",
      author,
      title
    } = req.query;

    const currentPage = Math.max(1, Number(page) || 1);
    const perPage = Math.min(100, Math.max(1, Number(limit) || 10));

    const skip = (currentPage - 1) * perPage;

    // Build filter
    const filter = {
      deletedAt: null
    };

    // Filter by author
    if (author) {
      if (!mongoose.isValidObjectId(author)) {
        return res.status(400).json({
          message: "Invalid author ID"
        });
      }

      filter.author = author;
    }

    // Search by project title
    if (title) {
      filter.title = {
        $regex: title,
        $options: "i"
      };
    }

    // Choose sorting order
    let sortOption = { createdAt: -1 };

    if (sort === "oldest") {
      sortOption = { createdAt: 1 };
    } else if (sort === "title_asc") {
      sortOption = { title: 1 };
    } else if (sort === "title_desc") {
      sortOption = { title: -1 };
    }

    // Get projects
    const projects = await Project.find(filter)
      .populate("author", "name email")
      .sort(sortOption)
      .skip(skip)
      .limit(perPage);

    // Count matching projects
    const totalProjects = await Project.countDocuments(filter);

    res.status(200).json({
      page: currentPage,
      limit: perPage,
      totalProjects,
      totalPages: Math.ceil(totalProjects / perPage),
      projects
    });

  } catch (error) {
    next(error);
  }
};
```

Make sure your controller imports both models and utilities:

```js
const mongoose = require("mongoose");
const Project = require("../models/Project");
```

Keep your existing exports and other controller functions.

## 9. Important MongoDB Query Operators

| Operator | Meaning |
|---|---|
| `$gt` | Greater than |
| `$gte` | Greater than or equal |
| `$lt` | Less than |
| `$lte` | Less than or equal |
| `$ne` | Not equal |
| `$in` | Matches any value in an array |
| `$regex` | Pattern-based text matching |
| `$options: "i"` | Case-insensitive matching |

Example:

```js
const projects = await Project.find({
  createdAt: {
    $gte: new Date("2026-01-01"),
    $lte: new Date("2026-12-31")
  }
});
```

This finds projects created during 2026.
