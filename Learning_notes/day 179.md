## 1. Today's Learning: Data-Layer Refactoring

### What is the Data Layer?

The data layer is the part of an application responsible for communicating with the database.

In our Learning Tracker API, MongoDB stores project information, and Mongoose helps Node.js communicate with MongoDB.

The data layer handles operations such as:

- Retrieving documents.
- Creating documents.
- Updating documents.
- Deleting documents.
- Searching and filtering data.

### Understanding the Application Layers

Our backend application has different layers.

```text
Client
  |
  v
Routes
  |
  v
Controllers
  |
  v
Services
  |
  v
Data Layer
  |
  v
Mongoose Models
  |
  v
MongoDB
```

Each layer has a separate responsibility.

| Layer | Responsibility |
|---|---|
| Routes | Define API endpoints |
| Controllers | Handle HTTP requests and responses |
| Services | Handle application logic |
| Data layer | Handle database operations |
| Models | Define MongoDB document structures |
| MongoDB | Store application data |

## 2. Why Refactor the Data Layer?

Imagine writing database queries directly inside every controller.

As the application grows, we may repeat the same queries in multiple places.

This creates problems:

- Duplicate database code.
- Difficult maintenance.
- Harder testing.
- Controllers become too large.
- Changes become more complicated.

Separating database operations makes the application easier to maintain.

## 4. Create the Repository Layer

Create `repositories/projectRepository.js`.

This file contains database queries.

```js
const Project = require("../models/Project");

// Find all projects
const findAll = async (filter = {}, options = {}) => {
  const {
    sort = { createdAt: -1 },
    skip = 0,
    limit = 10
  } = options;

  return Project.find({
    ...filter,
    deletedAt: null
  })
    .populate("author", "name email")
    .sort(sort)
    .skip(skip)
    .limit(limit);
};

// Find one project by ID
const findById = async (id) => {
  return Project.findOne({
    _id: id,
    deletedAt: null
  }).populate("author", "name email");
};

// Create a project
const create = async (data) => {
  return Project.create(data);
};

// Update a project
const updateById = async (id, data) => {
  return Project.findOneAndUpdate(
    {
      _id: id,
      deletedAt: null
    },
    data,
    {
      new: true,
      runValidators: true
    }
  ).populate("author", "name email");
};

// Delete a project permanently
const deleteById = async (id) => {
  return Project.findOneAndDelete({
    _id: id,
    deletedAt: null
  });
};

// Count active projects
const count = async (filter = {}) => {
  return Project.countDocuments({
    ...filter,
    deletedAt: null
  });
};

module.exports = {
  findAll,
  findById,
  create,
  updateById,
  deleteById,
  count
};
```

**What changed?**

Instead of writing database queries inside controllers or services, we now keep them inside one repository file.

## 5. Connect the Service to the Repository

Open `services/projectService.js`.

Import the repository:

```js
const projectRepository = require("../repositories/projectRepository");
```

Create service functions:

```js
// Get all projects
const getAllProjects = async (filter, options) => {
  return projectRepository.findAll(filter, options);
};

// Get one project
const getProjectById = async (id) => {
  return projectRepository.findById(id);
};

// Create a project
const createProject = async (data) => {
  return projectRepository.create(data);
};

// Update a project
const updateProject = async (id, data) => {
  return projectRepository.updateById(id, data);
};

// Delete a project
const deleteProject = async (id) => {
  return projectRepository.deleteById(id);
};

// Count projects
const countProjects = async (filter) => {
  return projectRepository.count(filter);
};

module.exports = {
  getAllProjects,
  getProjectById,
  createProject,
  updateProject,
  deleteProject,
  countProjects
};
```

The service now communicates with the repository instead of directly using the Mongoose model.

## 6. Understand the Difference

### Repository

The repository knows how to retrieve information from MongoDB.

Example:

```js
return Project.find({ deletedAt: null });
```

### Service

The service handles application logic and calls the repository.

Example:

```js
const getProjectById = async (id) => {
  return projectRepository.findById(id);
};
```

### Controller

The controller handles the HTTP request and response.

Example:

```js
const getProjectById = async (req, res, next) => {
  try {
    const project = await projectService.getProjectById(
      req.params.id
    );

    if (!project) {
      return res.status(404).json({
        message: "Project not found"
      });
    }

    res.status(200).json(project);
  } catch (error) {
    next(error);
  }
};
```

**Remember:**

- Repository = Database queries.
- Service = Application logic.
- Controller = HTTP request and response.
