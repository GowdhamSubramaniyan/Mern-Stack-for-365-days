## 1. What is Database Error Handling?

Database error handling means identifying database problems and returning meaningful responses instead of allowing the application to crash.

For example, imagine a user tries to create a project without providing a title.

Instead of crashing, our API should return a clear error:

```json
{
  "message": "Validation failed",
  "errors": ["Title is required"]
}
```

Good error handling makes an application more reliable and easier to debug.

## 2. Common MongoDB and Mongoose Errors

### A. Validation Error

Happens when data does not follow the rules in the Mongoose schema.

Example:

```js
{
  title: {
    type: String,
    required: true
  }
}
```

If the title is missing, Mongoose throws a validation error.

### B. Cast Error

Happens when MongoDB expects a particular data type but receives an invalid value.

Example:

```js
await Project.findById("invalid-id");
```

This can produce a `CastError`.

### C. Duplicate Key Error

Happens when we try to insert a value that already exists in a field with a unique index.

Example:

```js
email: {
  type: String,
  unique: true
}
```

If the same email already exists, MongoDB returns duplicate key error code `11000`.

**Important:** `unique: true` creates a unique index. It is not a normal Mongoose validator.

### D. Connection Error

Happens when the application cannot connect to MongoDB.

Possible reasons:

- Incorrect MongoDB connection string.
- Internet connection problems.
- MongoDB server unavailable.
- Incorrect database credentials.

### E. Document Not Found

Happens when a valid ID does not match any document.

Example:

```js
const project = await Project.findById(id);

if (!project) {
  return res.status(404).json({
    message: "Project not found"
  });
}
```

| Status | Meaning |
|---|---|
| 200 | Request successful |
| 201 | Resource created |
| 400 | Invalid request or validation error |
| 404 | Resource not found |
| 409 | Duplicate resource or conflict |

## 4. Build: Create a Central Error Handler

Instead of writing the same error response in every controller, we can create one central error-handling middleware.

Create a file:

```text
middleware/errorHandler.js
```

Add this code:

```js
const errorHandler = (err, req, res, next) => {
  console.error(err);

  // Mongoose validation error
  if (err.name === "ValidationError") {
    const errors = Object.values(err.errors).map(
      error => error.message
    );

    return res.status(400).json({
      message: "Validation failed",
      errors
    });
  }

  // Invalid MongoDB ObjectId
  if (err.name === "CastError") {
    return res.status(400).json({
      message: "Invalid ID format"
    });
  }

  // Duplicate key error
  if (err.code === 11000) {
    const field = Object.keys(err.keyValue || {})[0];

    return res.status(409).json({
      message: `A record with this ${field || "value"} already exists`
    });
  }

  // MongoDB connection unavailable
  if (
    err.name === "MongoServerSelectionError" ||
    err.name === "MongoNetworkError"
  ) {
    return res.status(503).json({
      message: "Database service is currently unavailable"
    });
  }

  // General server error
  return res.status(500).json({
    message: "Internal server error"
  });
};

module.exports = errorHandler;
```

---

## 5. Connect the Error Handler to Express

Open your existing `server.js`.

Import the middleware:

```js
const errorHandler = require("./middleware/errorHandler");
```

Add it after your routes:

```js
app.use("/api/projects", projectRoutes);

// Error handler must be registered after routes
app.use(errorHandler);
```

**Important:** Do not replace your existing `server.js`. Keep your current MongoDB connection, routes, middleware and configuration. Just add the import and error-handler registration in the correct places.

## 6. Refine Your Controller

Example of a project creation controller:

```js
const Project = require("../models/Project");

const createProject = async (req, res, next) => {
  try {
    const project = await Project.create(req.body);

    res.status(201).json({
      message: "Project created successfully",
      project
    });

  } catch (error) {
    next(error);
  }
};

module.exports = {
  createProject
};
```

Notice this line:

```js
next(error);
```

It sends the error to our central error-handling middleware.

This avoids repeating error-handling logic in every controller.

If you already have other controller functions, add or update this function without removing your existing exports.

## 7. Validate IDs Before Database Queries

We should check whether an ID is valid before searching MongoDB.

Example:

```js
const mongoose = require("mongoose");

if (!mongoose.isValidObjectId(req.params.id)) {
  return res.status(400).json({
    message: "Invalid project ID"
  });
}
```

This prevents invalid IDs from being passed to database queries.

## 9. Important Error Handling Concepts

| Concept | Meaning |
|---|---|
| try/catch | Catches errors in asynchronous code |
| next(error) | Passes errors to Express error middleware |
| ValidationError | Invalid schema data |
| CastError | Invalid data type or ObjectId |
| Error code 11000 | Duplicate key error |
| 400 | Bad request |
| 404 | Resource not found |
| 409 | Conflict |
| 500 | Internal server error |
| 503 | Database unavailable |
