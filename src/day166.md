# 1. Embedding vs Referencing

MongoDB provides two main ways to manage relationships between documents:

1. Embedding
2. Referencing

## What is Embedding?

Embedding means storing related information inside the same MongoDB document.

### Example

```js
{
  title: "Learning Tracker",
  description: "My first application",
  reviews: [
    {
      comment: "Amazing project",
      rating: 5
    },
    {
      comment: "Good work",
      rating: 4
    }
  ]
}
```

Here, reviews are stored directly inside the project document.

### When should we use Embedding?

- When related data is usually accessed together.
- When child data belongs to one parent.
- When the embedded data is relatively small.
- When we want to retrieve related information in one query.

## What is Referencing?

Referencing means storing the ObjectId of another document instead of storing all its information.

### Author document

```js
{
  _id: "author123",
  name: "John",
  email: "john@example.com"
}
```

### Project document

```js
{
  title: "Learning Tracker",
  author: "author123"
}
```

The project stores only the author's ID.

Mongoose can retrieve the referenced information using `populate()`.

### Example

```js
const projects = await Project.find()
  .populate("author", "name email");
```

### When should we use Referencing?

- When multiple documents share the same related data.
- When related data is large.
- When data needs to be updated independently.
- When one author has many projects.

## Embedding vs Referencing

| Embedding | Referencing |
|---|---|
| Stores related data inside the document | Stores another document's ID |
| Data stays together | Data stays in separate documents |
| No populate required | Can use populate() |
| Good for small related data | Good for shared related data |
| Example: Reviews | Example: Author |

### Remember

- Embedding = Keep related data together.
- Referencing = Connect separate documents using IDs.

# 2. What is MongoDB Text Search?

Text search allows us to search for words inside indexed text fields in MongoDB.

For example, imagine our application contains 100 projects.

A user searches for:

`JavaScript`

Instead of manually checking every project, MongoDB searches the indexed fields and returns matching documents.

MongoDB provides:

- Text indexes
- `$text`
- `$search`

---

# 3. Create a Text Index

Open the existing `models/Project.js` file.

Add this below your existing schema definition:

```js
projectSchema.index({
  title: "text",
  description: "text"
});
```

### Explanation

- `projectSchema.index()` creates an index.
- `title: "text"` makes the title searchable.
- `description: "text"` makes the description searchable.

Important: MongoDB supports one text index per collection. That index can include multiple fields.

# 4. Create the Search Controller

Open `controllers/projectController.js`.

Make sure the Project model is imported:

```js
const Project = require("../models/Project");
```

Add this function without deleting your existing controller functions:

```js
const searchProjects = async (req, res) => {
  try {
    const { q } = req.query;

    // Check whether search text exists
    if (!q || !q.trim()) {
      return res.status(400).json({
        message: "Please provide a search term"
      });
    }

    // Search projects using MongoDB text search
    const projects = await Project.find({
      $text: {
        $search: q.trim()
      }
    }).populate("author", "name email");

    res.status(200).json({
      count: projects.length,
      projects
    });

  } catch (error) {
    res.status(500).json({
      message: "Search failed",
      error: error.message
    });
  }
};
```

Add the function to your existing exports:

```js
module.exports = {
  // Keep your existing controller functions
  searchProjects
};
```

If you already have other exported functions, preserve them.

# 5. Create the Search Route

Open `routes/projectRoutes.js`.

Import the controller:

```js
const {
  searchProjects
} = require("../controllers/projectController");
```

Add the route:

```js
router.get("/search", searchProjects);
```

Important: Place `/search` before any dynamic route such as:

```js
router.get("/:id", getProjectById);
```

Otherwise, Express may interpret `search` as an ID.

# 8. How Does Text Search Work?

```js
Project.find({
  $text: {
    $search: "JavaScript"
  }
});
```

Explanation:

- `Project.find()` searches the Project collection.
- `$text` tells MongoDB to perform text search.
- `$search` specifies the words to search for.
- MongoDB checks the indexed text fields.
- Matching documents are returned.

### Important Points

1. `$text` requires a text index.
2. Text search is token-based, not ordinary substring matching.
3. You can index multiple text fields in one text index.
4. `populate()` retrieves related author information.
5. Text search does not automatically search every field in a document.
